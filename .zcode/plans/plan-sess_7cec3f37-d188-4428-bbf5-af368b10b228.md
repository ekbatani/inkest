# Crypto payments for Inkest (payments → credit balance, settled to a crypto wallet)

**Approach (defaults chosen since questions went unanswered):** a provider-abstraction with two drivers — `cryptomus` (hosted crypto gateway: per-payment invoice checkout page, webhook confirmation, funds auto-forwarded to the operator's wallet configured in the gateway dashboard) and `manual` (the app shows the operator's wallet address/asset/network from env; user transfers directly and submits a txid; an admin confirms in-app). Confirmed payments grant credits to a per-user ledger. `BILLING_PROVIDER` unset = feature disabled, surfaced gracefully like the AI provider's "not configured" state. Settlement asset configurable, default USDT/TRON.

## 1. Schema (`src/server/db/schema.ts` + generated migration)

- `payments`: id, userId+workspaceId (FK cascade), provider (`cryptomus`|`manual`), providerInvoiceId (nullable, unique), status (`pending`|`awaiting_confirmation`|`confirmed`|`failed`|`canceled`|`expired`|`rejected`), amountUsd (real), credits (real, rate locked at creation), paidAmount/paidAsset/paidNetwork/walletAddress/txHash, metadataJson, confirmedAt, expiresAt, timestamps. Index on userId.
- `creditLedger`: id, userId+workspaceId, delta (real), reason (`payment`|`admin_grant`), paymentId (nullable FK), note, createdAt. Unique `(paymentId, reason)` for idempotent crediting.
- Export `Payment`/`CreditLedger` types. Run `bun run db:generate` and commit the migration.

## 2. Server (`src/server/billing/`, house style: lazy env reads, `getCurrentUser` scoping, zod at boundary)

- `config.ts` — reads `BILLING_PROVIDER`, `CRYPTOMUS_MERCHANT_ID`, `CRYPTOMUS_API_KEY`, `BILLING_MANUAL_WALLET_ADDRESS/_NETWORK/_ASSET`, `BILLING_CREDITS_PER_USD` (default 100), `BILLING_MIN_TOPUP_USD`/`MAX` (5/500); `getBillingStatus()` returns only non-secret fields for the UI.
- `provider.ts` — driver interface `createInvoice(...)` → `{invoiceId, payUrl, expiresAt, payAsset, payNetwork, payAmount?, walletAddress?}` + webhook parsing/verification. Cryptomus: `POST api.cryptomus.com/v1/payment` with merchant + `sign = md5(base64(body)+apiKey)` headers, callback/return URLs; webhook `sign` verified with timing-safe compare, statuses mapped (paid/paidOver→confirmed, cancel→canceled, fail→failed, else pending-ish). Manual: invoice = env wallet instructions, no external call.
- `service.ts` — `getContext()` guard (like `notes/service.ts`); `createPayment(amountUsd)` (zod, min/max, 2-decimal clamp), `listPayments`, `getBalance` (sum of ledger), `getPaymentForUser`, `applyProviderCallback` — idempotent confirm via conditional `UPDATE ... WHERE status='pending'` then ledger insert; admin helpers `listAllPayments`, `confirmManualPayment`, `rejectManualPayment` gated on a billing admin check (DB role `admin`, deliberately not `isCloudDeployment()` so self-hosted operators can confirm manual payments — documented).
- `actions.ts` — `"use server"`: `createTopUpAction`, `getPaymentAction`, `getBillingOverviewAction`, `submitManualTxAction`, `confirmManualPaymentAction`, `rejectManualPaymentAction`, `grantCreditsAction` (admin), each zod-validated, `revalidatePath("/billing")`.

## 3. Webhook route `src/app/api/billing/webhook/route.ts`

POST; provider signature = the auth (route is outside the proxy matcher's allowlist, so it stays public); reads raw body, verifies, idempotently confirms + credits, always acks 200 after processing (Telegram-webhook pattern). Bad signature → 403. Unknown invoice → 200-ack + log.

## 4. UI

- `src/app/(app)/billing/page.tsx` — server component; redirect to `/signin` when unauthenticated (page is added to `src/proxy.ts` matcher: `/billing/:path*`); deep-link support `?payment=<id>`.
- `src/components/billing/billing-view.tsx` — client: balance card + ledger history; Top-up dialog (presets 5/10/25/50/100 + custom, min/max validation); Cryptomus flow → "Open payment page" + 5s status polling until confirmed; manual flow → wallet address/network/asset + copy buttons + txid submission; payments table; admin panel (visible to role-admin) listing all pending manual payments with txid, Confirm/Reject, and a small grant-credits form. Uses existing shadcn primitives, sonner toasts, `getPaymentAction` polling; RTL-safe (no absolute left/right), keyboard accessible via the existing dialog primitives.
- `src/components/app-shell/nav-items.ts` — add `{ label: "Billing", href: "/billing", icon: CreditCard }` to `settingsNav`.
